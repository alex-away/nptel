## introduction to codebook features
- **the concept**: a technique that makes a neural network more interpretable and controllable by forcing its internal, continuous activations to snap to a set of learned, discrete "codes."
- _analogy: instead of a painter mixing an infinite variety of colors on a palette (continuous activations), they are given a fixed set of 100 specific paint colors (discrete codes). the model learns to represent everything using only these fixed colors._
- **vector quantization**: the process of converting a continuous activation into its closest matching discrete code from the learned codebook.

## part 1: topic steering in a story generator
- this experiment uses a small model (tinystories) to show how codebook features can be used to control the content of generated text.
- **the process**:
    1. a generic prompt (e.g., "once upon a time") is fed to the model.
    2. a specific, pre-discovered code that represents a topic (e.g., the code for "baby" or "dragon") is manually activated in one of the model's layers.
    3. the model then generates a story that is strongly biased towards the activated topic.
- **quantitative evaluation**:
    - to prove the steering works, the experiment measures how often the target topic appears in the generated text, both with and without the intervention.
    - **results**: a topic like "dragon" might appear **0%** of the time in the baseline but jumps to **77.5%** when the "dragon" code is activated, showing that the intervention is highly effective.

## part 2: analyzing codes in an algorithmic task
- this experiment uses a model trained to predict sequences from a **finite state machine (fsm)** to analyze the properties of the learned codes.

### code purity analysis
- **goal**: to measure how "pure" a code is, meaning whether it represents a single, specific input or is used for many different inputs.
- **superposition**: the problem in standard neural networks where a single neuron might be used as part of representations for many different, unrelated concepts. this makes the model hard to interpret.
- **findings**: the analysis shows that in the early layers of the codebook model, the codes are very pure (e.g., one code corresponds to one specific input bigram like "0 -> 1"). this suggests that codebooks help the model learn to represent concepts cleanly, reducing superposition.

### steering and measuring influence with js divergence
- **goal**: to measure how much influence the code at a specific layer has on the final output.
- **patching**: the experimental technique used. the model is run with one input, but at a specific layer, the activation is replaced ("patched") with the code that would have been generated by a *different* input.
- **js divergence**: a statistical metric used to measure the difference between two probability distributions. a large js divergence means the two distributions are very different.
- **findings**: by measuring the js divergence between the original output and the patched output, the experiment shows which layers' codes have the most influence on the final prediction.

### grouping inputs by codes
- **hypothesis**: inputs that get mapped to the same internal code should produce similar final predictions.
- **findings**: the experiment confirms this by showing that the average js divergence between pairs of inputs that share a code is significantly smaller than the divergence between random pairs of inputs. this proves the codes are grouping functionally similar inputs together.
